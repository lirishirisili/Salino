# Salino iOS

Native SwiftUI port of the existing Android app. The structure mirrors the Kotlin app:

- `App`: SwiftUI entry point, navigation, dependency container.
- `UI`: SwiftUI screens, reusable components, theme.
- `ViewModels`: MVVM state and actions.
- `Domain`: repository and service protocols.
- `Data`: repository implementations.
- `Local`: SwiftData cache and pending sync queue.
- `Remote`: Firebase Auth and Cloud Firestore data sources.
- `Services`: duplicate detection, suggestions, voice parsing, utilities.
- `Models`: shared app models and enums.
- `Resources`: localizations, Info.plist generated by XcodeGen, app assets.
- `Tests`: XCTest coverage for pure services.

## Build From Windows

This folder is designed to build in the cloud. You do not need Xcode locally.

1. Create an iOS app in Firebase with bundle id `com.salino.sali`.
2. Download `GoogleService-Info.plist`.
3. Add a GitHub secret or Codemagic environment variable named `GOOGLE_SERVICE_INFO_PLIST_BASE64`:

   ```bash
   base64 -i GoogleService-Info.plist
   ```

   On Windows PowerShell you can generate the same value with:

   ```powershell
   [Convert]::ToBase64String([IO.File]::ReadAllBytes("GoogleService-Info.plist"))
   ```

4. Push the repository. GitHub Actions runs on `macos-latest`, installs XcodeGen, generates `Salino.xcodeproj`, resolves Swift packages, builds, and runs tests.

## TestFlight / App Store Prep

The unsigned simulator build works without Apple credentials. For TestFlight:

- Add Apple Developer Team ID as `DEVELOPMENT_TEAM`.
- Configure Codemagic or GitHub Actions with App Store Connect API key, signing certificate, and provisioning profile.
- Ensure Firebase iOS bundle id is exactly `com.salino.sali`.
- Replace the placeholder app icon with production App Store assets before submission.
